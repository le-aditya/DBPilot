# DBPilot

AI-powered database explorer and query assistant. Connect or upload a database,
see it as an ER diagram, and query it in plain English — the generated SQL is
always shown, always explained, and never allowed to write.

## Status

Phase 1 — scaffold. See `docs/superpowers/plans/` for the build plan and
`docs/superpowers/specs/` for the design document.

## Requirements

- Python 3.11
- Node 20+
- PostgreSQL 15 or newer

## Setup

```bash
psql -U postgres -h localhost -f scripts/bootstrap.sql

cd backend
py -3.11 -m venv .venv
.venv/Scripts/python -m pip install -e ".[dev]"
cp .env.example .env    # then fill in the real values
.venv/Scripts/alembic upgrade head
.venv/Scripts/python run.py --reload

cd ../frontend
npm install
npm run dev
```

## Layout

- `backend/` — FastAPI application, migrations, tests
- `frontend/` — React + Vite client
- `docs/` — design document, plans, normalisation write-up, benchmarks
- `scripts/` — cluster bootstrap and demo seeding

Start the server with `run.py`, not `uvicorn app.main:app`. On Windows,
uvicorn builds a ProactorEventLoop that psycopg 3 cannot drive; `run.py`
installs a selector loop first so database queries work.

## Safety

No query generated by the model, and no query typed by a user, can modify data.
Four independent layers enforce this: ownership scoping, a `sqlglot` parse gate
that allows only `SELECT`, a read-only transaction that always rolls back, and a
per-project PostgreSQL role holding `SELECT` on exactly one schema. See section 6
of the design document.
